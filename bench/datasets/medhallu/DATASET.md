# MedHallu via MedHELM: dataset notes

Checked 2026-09-21.

## What it is

- **Items:** MedHallu (`UTAustin-AIHealth/MedHallu`, MIT licence), config
  `pqa_labeled`: 1,000 PubMedQA questions with the abstract as "knowledge", the
  abstract's own conclusion as the factual answer, and a machine-generated
  hallucinated answer, tagged with a difficulty and a hallucination category.
- **Test set:** the exact 1,000 instances Stanford CRFM's MedHELM v4.0.0 used
  (scenario `medhallu`): one answer per question, 520 factual and 480
  hallucinated. `prepare.py` reads them from MedHELM's public bucket
  (`gs://crfm-helm-public/medhelm/benchmark_output/runs/v4.0.0/`) and confirms
  every gold label against the source dataset.
- **Published columns:** 13 LLMs, one prediction per item, with MedHELM's
  per-item runtime and token counts. `prepare.py` checks that all 13 runs used
  the same ids, questions and answers, and that accuracy recomputed from the
  downloaded predictions equals MedHELM's reported `exact_match` for every
  model (80.1% to 92.6%).
- **Dev set:** 500 items sampled with a fixed seed from `pqa_artificial`
  (9,000 rows, disjoint questions), built the same way as the test items. Its
  labels and hallucinations are fully machine-generated, so treat dev accuracy
  as a tuning signal only.

## What the comparison can claim

- **Accuracy, item by item.** Same items, same gold, same scoring (an
  unparseable answer is wrong, as in MedHELM: o3-mini has 7).
- **Not identical prompts.** MedHELM sent one text prompt and asked for "0" or
  "1". Jev gets the same three pieces of text as named state fields and one
  yes/no question. Say so wherever the table is shown.
- **Not latency.** The published runtimes come from Stanford Healthcare
  deployments (Llama 3.3 shows 0 ms, served from cache). Jev's latency is
  measured from your machine through OpenRouter. Show them in separate columns
  or footnote them; never rank across the two.
- **Cost only by estimate.** MedHELM reports no cost. About 700 input tokens
  per item times a list price gives a floor; reasoning models also bill hidden
  reasoning tokens that the published counts leave out.
- **Model vintage.** The 13 models date from 2024 to August 2025. The table
  says nothing about newer models unless you run them yourself.

## Known weak points

- Hallucinated answers were generated by an LLM; they are not naturally
  occurring errors.
- Many abstracts turn on p-values and effect sizes. Numeric comparison is a
  documented Jev weak spot, so read the `difficulty=hard` slice and the false
  negatives before drawing conclusions.
- `category` slices other than "Misinterpretation" and "Incomplete
  Information" are too small to read (15 and 3 items).
- The test items are public and may be in LLM training data. That can only
  favour the published LLM columns, not Jev's comparison against them.
